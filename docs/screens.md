# 画面仕様

左メニューの「監視対象」で対象 DB を絞り込めます（すべて／個別）。選択はブラウザに保存されます。

## サマリー

現在の状態を表示します（5 秒ごとに自動更新）。

| 項目 | 内容 |
|---|---|
| 接続数 | 接続中のセッション数 |
| アプリ数 | 接続中セッションのアプリ（IIS プール・exe 等。[process-info.md](process-info.md)）の種類数 |
| 端末数 | 接続中セッションの実行端末（MACHINE）の種類数 |
| 履歴数 | 切断済みセッションの件数 |
| 本日のログオン | 本日ログオンしたセッション数 |
| DB Linkの可能性 | 接続中のうち ORACLE.EXE / oracle@host からの接続数 |

[接続アプリ](#接続アプリ) の表をスクロールせずに見られるよう、サマリー部分は小さくまとめています。数値は 1 行の小さいタイル（説明はマウスを載せると表示）、監視対象の状態（収集中／取得失敗 n 回／停止）は 1 行のバッジで表示し、取得エラーがあればその下に出します。監視対象ごとの内訳の表と、接続数の多いアプリ・端末のランキングは折りたたんでいます（開閉はブラウザに保存）。その下に接続アプリの表を表示します（「アプリ数」のタイルをクリックすると接続アプリの表へ移動します）。

Oracle 内部プロセス（`ORACLE.EXE (J000)` などのジョブ・パラレル実行・バックグラウンド）は数えません。DB Link の可能性があるもの（括弧なしの `ORACLE.EXE` / `oracle@host`）は数えます。タイル（アプリ数を除く）やランキングをクリックするとセッション履歴に遷移します。

## セッション履歴

- 「対象」で表示するものを選びます：**セッション**（既定。監視対象のセッション）／**DB Link利用元**（DB Link 接続元 DB 上で DB Link を使っていたセッション）／**すべて**（両方を同じ一覧にログオン順で混ぜる）。DB Link 利用元の行は下記「DB Link 利用元の行」のとおりです。
- 検索しなくても表示し、**ログオン時刻が新しい順** に並べます（50 件ずつページング、10 秒ごとに自動更新）。
- Oracle 内部プロセスと、このシステム自身（Batch・Server）の接続は既定で表示しません（「Oracle 内部プロセス・このシステムの接続も表示」をチェック、または種別で選ぶと表示）。このシステムの接続は MODULE が `OracleSessionHistory`、または PROGRAM が `OracleSessionHistory.` で始まるもので判定します。
- DB Link の可能性がある `ORACLE.EXE` の行は、DB Link 接続元 DB 上で利用元を特定できた場合に「DB Link 経由: アプリ（端末）」を表示します。
- 検索条件：キーワード（端末・アプリ・補足・実行ファイル・コマンドライン・プログラム・ユーザ・スキーマ・モジュール・アクション・CLIENT_INFO・ジョブ名・SQL）、状態（接続中／切断済み）、種別、実行端末、アプリ、接続ユーザ、実行ユーザ（OSUSER・プロセスの実行ユーザ）、期間（その期間に接続していたセッション）
- 「端末・アプリを完全一致」：接続アプリ・サマリーのランキングから開くとチェックされます。DB Link 経由で接続元を特定した `ORACLE.EXE` の行は、接続元の端末・アプリで一致させます。端末名は前後の空白を除いて保存します。チェックしたまま端末・アプリの欄を書き換えると、部分一致に戻ります。
- DB Link 経由で接続元を特定した `ORACLE.EXE` の行は、アプリの下に「DB Link 経由: 接続元のアプリ（接続元の端末・接続元の実行ユーザ）」を表示します。
- 列：状態、監視対象、ログオン、切断（推定の場合は「推定」）、接続時間、実行端末、**アプリ**（アプリ名と補足の 2 行。プロセス情報が未取得・失敗の場合はバッジ）、実行ユーザ、接続ユーザ（スキーマが異なれば併記）、モジュール、種別
- 行をクリックすると詳細パネルを表示：接続アプリ（プロセス情報・取得状態）、利用システムの特定情報（Oracle）、ジョブ・親セッション、DB Link の接続元、SQL

### DB Link 利用元の行

DB Link 接続元 DB で、DB Link を使っていたセッションです（設定 → DB Link 接続元 で登録。旧「DB Link 利用元」画面）。同じ列に次のように表示します。

| 列 | 内容 |
|---|---|
| 状態 | 「DB Link利用元」 |
| 監視対象 | DB Link の先の監視対象 |
| 切断 | 「最終確認」（接続元 DB 上で最後に DB Link の利用を確認した時刻） |
| 接続時間 | ログオン 〜 最終確認 |
| 実行端末・アプリ・実行ユーザ・接続ユーザ | 接続元 DB 上のセッションの値。アプリは接続元端末のプロセス情報で特定したアプリ（取れるまでは PROGRAM）とコマンドライン（[process-info.md](process-info.md)） |
| モジュール | モジュールと、DB Link を使っていた SQL |
| 種別 | 接続元 DB の名前、DB Link、特定方法（プロセス一致／SQL／シノニム） |

- 監視対象側のセッションを特定できた（プロセス一致）行は、クリックでそのセッションの詳細パネルを開きます。
- 検索条件はキーワード・実行端末・アプリ・接続ユーザ・実行ユーザ・期間・完全一致が効きます。状態・種別・Oracle 内部プロセスは監視対象のセッションだけの条件のため、「DB Link利用元」では効かず（接続アプリの行の条件のうち実行ファイル以外も同じ）、「すべて」でこれらの条件を指定した場合は DB Link 利用元を表示しません（どちらも一覧の上に表示します）。「すべて」の並べ替え・ページの切り出しは DB で両方をまとめて（UNION ALL）行います。

## 接続アプリ

サマリーのメインとして、サマリー部分の下の残りの高さいっぱいに表示します。表の中だけがスクロールし、見出し・合計の行・先頭列（端末／アプリ）・右端の「セッション履歴」列・スクロールバーは常に見えます。木の形で、ログオン回数を期間別に表示します（折りたたみはありません）。Oracle 内部プロセスは含みません。

- **列**：実行端末 / アプリ・担当者・実行ユーザ・接続中・最終確認・期間別の件数・セッション履歴（「履歴 →」でその行のセッション履歴を開く）の順です。
- **行の情報**：各行（端末・実行ファイル・アプリ・DB Link 接続元）に、日本語名・メモ・担当者（メイン 1 人、サブ 10 人まで）を設定できます。行の ✎（マウスを載せると表示）か担当者の欄をクリックして編集します。日本語名は元の名前の前に太字で、メモは名前の下に表示します。すべて空にして保存すると設定を外します。担当者は AD から名前・アカウント・メールアドレスで検索して選びます（自由入力はできません。下記「担当者の AD 検索」）。担当者の欄には選んだ時点の表示名を出し、アカウントはツールチップに出します。行は上の段からの経路（例：端末 WEB01 → w3wp.exe → IIS: Foo）で識別して `AppNodeNotes`（担当者は `AppNodeAssignees`）に保存するため、同じアプリでも端末が違えば別の行です。監視対象には依存しません。端末名やアプリ名が変わると、別の行として扱われます。
- **担当者で絞り込み**：見出しの行の「担当者」（設定済みの担当者）で選んだ人（AD のアカウントで一致させる）がメインかサブの行と、その下の段すべて、上の段（経路）を表示します。「未設定」は、自分にも上の段にも担当者がいない最下段の行を表示します。合計は表示している端末の件数です（端末の件数には、表示していない下の段の件数も含まれます）。キーワードの絞り込みは日本語名・メモを対象にしません。
- **担当者の AD 検索**：Server が `GET /api/directory/people` で AD を検索します（`IUserDirectory.SearchAsync`。Windows 以外はデモの疑似ディレクトリ）。**Server の実行アカウント**（IIS のアプリケーションプールの ID）のドメインで、無効化されていないユーザを `anr`（名前・姓・名・アカウント・メールの前方一致）と表示名の部分一致で探し、最大 20 件を返します。アプリケーションプールが `ApplicationPoolIdentity` の場合は、ドメインに参加したサーバーのコンピュータアカウントで AD を読みます（通常は追加の権限は不要）。AD に接続できない場合は検索欄にエラーを表示します（設定済みの担当者の表示・絞り込みには影響しません）。

```
端末A
  app1.exe
  w3wp.exe
    Pool1                 … IIS のアプリケーションプール（補足にサイト／パス）
    (プール不明)          … プールを特定できていないもの
  sqlplus.exe
    月次集計.bat          … 実行元（バッチ・スクリプト、手で実行した cmd.exe、起動したプログラム）
  ORACLE.EXE              … 端末A が DB サーバーで、DB Link 経由で使われている場合
    DB Link 基幹DB        … 接続元を特定した DB Link 接続元（設定で登録した名前）
      端末C               … 接続元の端末
        app3.exe          … 接続元のアプリ
      端末F
        w3wp.exe
          Pool3
        sqlplus.exe
          日次.cmd
    (接続元不明)          … 接続元を特定できていない ORACLE.EXE
端末B
  …
```

- 実行ファイルの段は、アプリ名から決めます（`IIS: プール` は w3wp.exe、`sqlplus.exe: 実行元` は sqlplus.exe、それ以外は PROGRAM。`AppIdentifier.SplitForTree`）。下の段が無い実行ファイルは 1 行です。
- DB Link 経由のセッションは、DB サーバーの端末（`ORACLE.EXE` の MACHINE）の下に置き、DB Link 接続元 → 接続元の端末 → 接続元のアプリの段にします（接続元の端末を一番上の段にはしません）。
- 各段は「本日〜1ヶ月」の多い順です（「(不明)」の行は最後）。端末の行は監査証跡のログオン件数です（下記。取得できない場合は下の段の合計）。
- 「セッション履歴」列の「履歴 →」ボタンで、その行のセッション履歴を開きます（端末は MACHINE の完全一致、DB Link 接続元・接続元の端末・経由・実行ファイル・アプリの条件付き。一覧の上部にバッジで表示し、✕ で外せます）。
- 「実行ユーザ」はすべての段に、表示名とアカウントの 2 行で表示します（下記の AD の表示名）。複数のユーザがいる行は、ログオンの最も多いユーザと「他 N 名」を表示し、ツールチップに全員を出します。DB Link 経由の行は、DB サーバー側の OSUSER ではなく接続元の実行ユーザ（接続元端末のプロセスの実行ユーザ、無ければ OSUSER。`TrackedSession.LinkOriginUser`）です。

## 実行ユーザの表示名（AD）

セッション履歴（DB Link 利用元の行を含む）・詳細・接続アプリの「実行ユーザ」は、アカウント（OSUSER・プロセスの実行ユーザ）の代わりに AD の `displayName` を表示します（アカウントはツールチップ、詳細では「表示名（アカウント）」）。表示名が取れないアカウントはそのまま表示します。

- Batch が 10 分ごと（`Collector:UserNameMinutes`）に、直近 2 ヶ月に観測した実行ユーザのうち未取得・取得から 1 日以上たったものを AD に問い合わせ、`DirectoryUsers` に保存します（`UserNameService`）。セッションの収集とは別のループで、AD に接続できなくても収集に影響しません（警告ログを 1 回出します）。
- `DOMAIN\user` はそのドメインの `sAMAccountName`、`user@domain` は `userPrincipalName`、`user` だけの場合は Batch の実行アカウントのドメインの `sAMAccountName` で探します。`IIS APPPOOL\…`・`NT AUTHORITY\…`・コンピュータアカウント（`…$`）は問い合わせません。
- AD には **Batch の実行アカウント**（サービスのログオンアカウント）で接続します。ドメインのユーザ（またはドメイン参加したサーバーの LocalSystem）であれば、通常は追加の権限は不要です。
- セッション履歴の「実行ユーザ」とキーワードは、表示名でも検索できます。
- Windows 以外（macOS 等のデバッグ）では、デモの実行ユーザに疑似の表示名を返します（`DemoUserDirectory`）。

### 端末のログオン数（監査証跡）

端末の行の件数は、監視対象 DB の `DBA_AUDIT_SESSION`（成功したログオン）の件数です。下の段（実行ファイル・アプリ）はこのシステムが取得したセッション数のため、短いセッションの取りこぼし分だけ端末の行より少なくなることがあります。

- Batch が 10 分ごと（`Collector:AuditLogonMinutes`）に、「2 ヶ月前の同日」から本日までの日・端末（USERHOST）ごとの件数を取得し、`AuditLogonCounts` に保存します（このシステム自身の接続は除く）。2 回目以降は前回取得した日（途中までの件数）以降だけを取り直し、期間より古い件数は消します。
- 監査証跡には PROGRAM が無いため、監査の件数は **端末の行だけ** に使います。履歴に無い端末も、監査の件数だけの端末の行として表示します。
- 監査の件数を取得できていない監視対象・期間（権限が無い・取得前など）は、端末の行も履歴の件数（下の段の合計）にし、その列に「※」を付けます。画面上部に監査の件数の期間と取得日時（失敗した場合は理由）を表示します。
- 絞り込み時は、端末名が一致する場合だけ監査の件数を使います（アプリ名等で一致した端末は、一致した行の履歴の件数）。
- 権限は [oracle-privileges.md](oracle-privileges.md)。

| 列 | 期間 |
|---|---|
| 本日 | 本日 0:00 以降 |
| 1日前〜6日前 | 各日の 0:00〜24:00 |
| 本日〜1ヶ月 | 1 ヶ月前の同日 0:00 以降（本日を含む） |
| 1ヶ月〜2ヶ月 | 2 ヶ月前の同日 0:00 〜 1 ヶ月前の同日 0:00 |

- 回数は Oracle の `logon_time` で集計します。
- 日別の列は回数に応じて背景色を付けます。「履歴 →」ボタンでその端末・アプリのセッション履歴を表示します。
- 「本日〜1ヶ月」の多い順に並べます。

## 設定

- 監視対象の追加・編集・削除、接続テスト
- 監視対象ごとの「DB Link 接続元」：接続元 DB の接続文字列を入力 →「DB Link 一覧を取得」→ 監視する DB Link を選択 → 保存
- 接続文字列のパスワードは `********` で表示され、変更しなければ保存済みの値が使われます。
- 「プロセス情報の取得」：有効／無効、アカウント・パスワード、DNS サフィックス、タイムアウト、対象外の端末、接続テスト（[process-info.md](process-info.md)）

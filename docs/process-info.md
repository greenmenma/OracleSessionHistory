# 接続アプリの特定（接続元サーバーのプロセス情報）

`gv$session` の PROGRAM・OSUSER はクライアントの申告値で、`w3wp.exe`（IIS）のように同じ名前のアプリを区別できません。
そこで Batch が接続元サーバー（MACHINE）に WMI/CIM で問い合わせ、`gv$session.process` の PID からプロセスの情報を取得して「アプリ」を確定します。

## 取得する情報

| 項目 | 取得元 |
|---|---|
| プロセス名・実行ファイル・コマンドライン・開始時刻・親プロセス | `root\cimv2` の `Win32_Process` |
| 実行ユーザ | `Win32_Process.GetOwner` |
| IIS アプリケーションプール名 | w3wp.exe のコマンドライン（`-ap "名前"`） |
| IIS のサイト／アプリのパス | `root\WebAdministration` の `Application`（IIS 管理スクリプトおよびツールが入っている場合のみ） |
| 実行元（親・その親…） | `Win32_Process.ParentProcessId` をたどる。sqlplus.exe 等は 3 段まで（親が子より後に開始していれば PID の再利用とみなして止める） |

## アプリ名の決め方

| 条件 | アプリ | 補足 |
|---|---|---|
| w3wp.exe（プール名あり） | `IIS: プール名` | サイト／パス（無ければ実行ファイル） |
| dotnet.exe xxx.dll | dll のファイル名 | dll のパス |
| java.exe -jar xxx.jar | jar のファイル名 | jar のパス |
| sqlplus.exe（実行元が取れた場合） | `sqlplus.exe: 実行元`。実行元は、バッチ・スクリプト（cmd.exe の .bat/.cmd、PowerShell の .ps1 等）のファイル名、対話のシェル（手で実行）はシェル名（`cmd.exe`）、それ以外は起動したプログラム名（`jp1ajs2.exe`、`java.exe` 等）。`cmd /c sqlplus …` のようにコマンドを渡されただけのシェルはさらに親をたどる | `実行元: スクリプトのパス（cmd.exe ← jp1ajs2.exe）` |
| その他 | 実行ファイル名 | フォルダ |
| プロセス情報なし | PROGRAM（w3wp.exe で OSUSER が `IIS APPPOOL\名前` なら `IIS: 名前`） | MODULE |

ロジックは `AppIdentifier`（Core/Processes）にあります。実行元でアプリを区別する exe は `AppIdentifier.LaunchedTools`（現在は sqlplus.exe）で、必要に応じて追加します。

### パスワードを隠す

コマンドライン（本体・実行元）は、保存する前にパスワードを `********` にします（`ClientProcessRules.MaskCredentials`）。アプリ名は隠す前の値で決めます。隠す形は次のとおりです。

- `ユーザ/パスワード` に接続先（`@`）が続くもの：`scott/tiger@DB`、`scott/"p@ss"@DB`、`jdbc:oracle:thin:scott/tiger@host:1521:orcl`
- Oracle のツール（sqlplus・sqlldr・expdp/impdp・rman 等。exp/imp は `exp.exe` の形のみ）とその実行元のコマンドライン中の `ユーザ/パスワード`（`userid=scott/tiger`、バッチの引数）。ただし `ctl/x.ctl` のように拡張子の付いたファイルのパスらしい値は隠しません
- `Password=xxx`・`PWD=xxx`（接続文字列）、`/pwd=xxx`、`--password xxx`、`-password=xxx`

ユーザとパスワードを別々の引数で渡す形（`run.bat scott tiger`）は判別できないため隠しません。以前のバージョンで保存した Oracle のツールのコマンドラインは、移行時に消します。

### 実行元の判定でできないこと

- コマンドプロンプトで手で .bat を実行した場合、bat は同じ cmd.exe の中で動くため、実行元は `cmd.exe`（手で実行）になります。
- 親プロセスの開始時刻が取れない場合は、PID の再利用（親が終了して別のプロセスが同じ PID を使った）を判定できません。

## 取得の流れ

- Batch の `ProcessInfoCollector` が 10 秒ごと（`Collector:ProcessInfoSeconds`）に、次のセッションを端末ごとにまとめて問い合わせます。
  - 接続中の **クライアント** セッション（DB Link の可能性・Oracle 内部プロセス・このシステム自身の接続は対象外）
  - **DB Link 利用元**（DB Link 接続元 DB 上で DB Link を使っていたセッション）。接続元端末の `gv$session.process`（クライアント PID）でプロセスを調べます。最後に観測してから 10 分を過ぎたものは調べません（接続元セッションが終了し、PID が再利用されている可能性があるため。未取得・取得失敗のまま残っていたものは理由を付けて「対象外」にします）。利用元の PROGRAM が Oracle のプロセス（ジョブ `ORACLE.EXE (J000)`、さらに別の DB Link からの `ORACLE.EXE` 等）の場合は、端末が DB サーバー自身のため調べません
- 特定した DB Link 利用元のアプリは、「DB Link 利用元」画面と、セッション履歴の `ORACLE.EXE` の行（「DB Link 経由: アプリ（端末）」）に表示します。接続アプリ表・サマリーのランキングでは、その `ORACLE.EXE` のセッションを接続元の端末・アプリとして数えます（`TrackedSession.LinkOriginMachine` / `LinkOriginApp`）。接続元のアプリが未確定（プロセス情報の取得前・失敗）の間は、接続元の PROGRAM の値でまとめ、確定すると確定したアプリに移ります。DB Link 接続元の削除・保持期間による利用元の削除・利用元の付け替えの後は、接続元を外す（付け直す）ため、`ORACLE.EXE` の行に戻ります。
- セッション収集とは別のループで動くため、問い合わせが遅い・失敗してもセッションの記録や切断の判定には影響しません。
- 接続は DCOM で行います（WinRM は使いません。権限の無い環境ではタイムアウトまで待たされて取得できないため）。端末名で名前解決できない場合は、設定の DNS サフィックスを付けて再試行します。
- 接続できない端末は 1 分 → 5 分 → 15 分 → 60 分と間隔を空けて再試行します（ログは最初の失敗と回復時のみ）。
- PID が再利用された別のプロセスを誤って紐付けないよう、次の場合は「不一致」として紐付けません。
  - プロセスの開始がログオンより 5 分以上後
  - PROGRAM が `*.exe` で、プロセス名と異なる

| 状態 | 意味 |
|---|---|
| 取得待ち | まだ問い合わせていない |
| 取得済み | プロセス情報でアプリを確定した |
| 終了済み | 問い合わせたがプロセスが無かった（再試行しない） |
| 不一致 | 別のプロセスと判断した（再試行しない） |
| 取得失敗 | 接続できない・アクセス拒否など（時間をおいて再試行） |
| 対象外 | 取得が無効の間に接続した、取得前に切断した、PID・端末名が無い、対象外端末、DB Link の可能性・Oracle 内部プロセス・このシステム、観測されなくなった DB Link 利用元 |

設定を保存すると（有効の場合）、接続中で「対象外」になっているクライアントセッションと観測中の DB Link 利用元を「取得待ち」に戻して調べ直します（対象外端末の変更・無効から有効への切り替えを反映するため）。

## 設定

画面の「設定」→「プロセス情報の取得」で設定します。

| 項目 | 内容 |
|---|---|
| プロセス情報を取得する | 有効／無効 |
| アカウント | `DOMAIN\user` または `user@domain`。**空の場合は Batch の実行アカウント**（サービスのログオンアカウント）で接続 |
| パスワード | 接続文字列と同様に履歴 DB に保存し、API・画面・ログには出しません |
| DNS サフィックス | 端末名で名前解決できない場合に付ける（例：`corp.example.local`） |
| タイムアウト | 1 サーバーあたり（既定 10 秒） |
| 対象外の端末 | 問い合わせない端末（カンマ区切り、`*` はワイルドカード。例：`PC-*`） |

「接続テスト」は **Server（IIS）から** 実行します。Batch とは実行アカウント・ネットワーク経路が異なる場合があります。

## 接続先サーバーの準備

ドメインの共通アカウント（例：`CORP\svc_osh`）に、各アプリサーバーで次の権限が必要です。最も簡単なのはローカルの Administrators に追加することです。

**DCOM**
- ファイアウォールの「Windows Management Instrumentation (WMI-In)」を許可（135/TCP と動的 RPC ポート）。
- 管理者以外の場合：ローカルグループ「Distributed COM Users」に追加し、`wmimgmt.msc` で `root\cimv2`（IIS のサイト情報も取る場合は `root\WebAdministration`）に「アカウントの有効化」「リモートの有効化」を付与。

**共通の注意**
- 他のユーザ（IIS のプール ID など）のプロセスのコマンドライン・実行ユーザは、管理者権限が無いと取得できないことがあります（その場合アプリ名は PROGRAM のままになります）。
- IIS のサイト／パスは「IIS 管理スクリプトおよびツール」（Web-Scripting-Tools）が入っているサーバーのみ取得できます。無くてもプール名は取得できます。
- Batch・Server が Windows 以外で動いている場合は取得できません（「この OS ではプロセス情報を取得できません」）。
